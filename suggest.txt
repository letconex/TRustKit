A few solid improvements I’d suggest for this Rust file:

Fix the colour handling

colour: Option<String> with default_missing_value = "darkblue" is good, but the code then passes colour.as_deref().unwrap_or("").
That means “no color” and “empty string” behave the same.
Consider making the logic explicit with an enum or a helper like format_target_text(target, colour).


Reduce repeated error creation in parse_tsv_line

The function has several similar io::Error::new(...) calls.
You could simplify by using a small helper, or return a custom error type for cleaner diagnostics.


Improve open_nonempty_reader

The name suggests it checks for non-empty content, but it also skips whitespace-only files.
Consider renaming to something like open_reader_with_content_check.
Also, the BOM handling and buffer scanning could be simplified by reading a small prefix once instead of looping manually.


Avoid println! for argument debugging

println!("Arguments: {:?} {:?}", args, formats); looks like debug output.
Better use a logging framework or remove it in release code.


Make output extension handling safer

input_path.with_extension("dsl") is straightforward, but if the input already ends in something like .tsv, that’s fine.
If you want predictable naming, you could derive output from the stem explicitly.


Separate responsibilities in run_args

run_args does parsing, validation, file opening, conversion, and final display.
Breaking this into smaller helpers would make it easier to test and maintain.


Use a custom error type

Right now everything is boxed as Box<dyn std::error::Error>.

Handle empty lines more explicitly
